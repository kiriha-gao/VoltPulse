# VoltPulse V1 项目实施方案

## AI 主控、低人工干预版

方案版本：2.0 ｜ 2026-09-21

本文整合并替代原《VoltPulse V1 项目实施规格书》中的工作流、优先级与验收规则。本文是实施方案，不表示项目已经开发、数据源已经验证或网站已经发布。文中的命令、路径、参数为待实现约定；实际平台能力、数据可用性和成本须在实施阶段验证。

## 1. 项目目标与边界

**VoltPulse（电脉）——中国电力现货市场与储能运行分析平台。**

以一个省级现货市场的可追溯公开数据为基础，自动完成采集、质量检查、电价分析、储能调度模拟、策略对比和网页更新，形成可复现、可展示、可解释的求职研究项目。

核心交付目标：

1. 真实数据持续进入系统，来源和修订可追溯。
2. 储能模型在明确假设下正确运行。
3. 自动任务处理新增及修订数据，失败时保留正确历史。
4. 手机可访问的页面展示最新有效结果和数据状态。
5. 报告、简历描述与面试材料均以实际成果为依据。

本项目采用价格接受者假设，不影响市场出清价格，不执行真实交易。模型净收益不等于实际项目财务净利润；默认不含投资成本、固定运维、税费、完整结算规则及并网约束。缺少负荷或网络数据时，不声称已验证电网调节效果或新能源消纳效果。

实施目标是低干预、可恢复运行，不承诺任何外部数据源永久可用或绝对零维护。

## 2. 最高执行原则

- 先验证数据，再扩大开发；第一条闭环包含自动化和预览。
- 可先用 fixture 验证代码，但只有真实数据与模型验收均通过，才能发布真实分析。
- 每项任务完成后由主控 AI 自动推进下一项，不向用户逐步询问是否继续。
- 不编造接口、数据、执行记录、测试结果或研究数字。
- 不为通过验收而删测试、放宽约束、篡改数据或隐瞒错误。
- 简单实现优先；正确性问题不能通过简化而掩盖。
- 所有自动修复均受次数、权限与范围限制。
- 会话中断不等于任务取消；通过项目状态文件恢复工作。
- 开发自动化与日常运行分离：AI 负责开发和诊断，日常 pipeline 使用确定性程序，不强依赖大模型调用。

## 4. AI 组织方式

### 4.1 主控负责制

主控 AI 负责范围、接口、任务状态、依赖、集成、验收与交付。专项角色按需承担数据、模型、前端与自动化；审查角色独立检查结果。

这是一套职责结构，不强制同时运行六个 Agent。执行环境支持且授权允许时可委派专项工作；否则按角色顺序完成。不得假装进行了独立审查：同一执行者自查时明确记录。

### 4.2 并行条件

先冻结数据契约和配置，再允许模型与页面并行。每个执行角色明确文件所有权；共享 Schema 或接口变更交回主控统一处理。角色之间不能让用户充当消息中转。

### 4.3 任务单

每项任务必须包含：任务 ID、目标、输入、输出、依赖、验收命令、失败回退、完成证据。状态限定为 pending / running / passed / blocked / skipped。

只有验收通过才标记 passed。可选功能缺数据可以 skipped；核心功能不能通过 skipped 宣称 V1 完成。

## 6. 默认架构

采用模块化单体。默认 Python + Pandas、按日分区 Parquet、JSON 元数据、支持二进制约束的 MILP 求解器、静态 HTML + Plotly、pytest、YAML。

优先考虑 GitHub Actions 执行定时任务、GitHub Pages 承载静态展示；这是候选默认，实施时检查实际可用性、账号权限、网络、存储和费用。用户已指定其他托管环境时遵从指定环境。选定后记录并固定，不反复迁移。

SQLite 不作为必须依赖；只有明确查询需求才加入。前端只读取预计算结果，不提供任意参数实时求解。敏感性分析通过预计算场景切换展示。

依赖只保留一个权威声明入口及可复现的锁定记录；不得同时维护互相冲突的依赖清单。

## 7. 关卡 G0：数据可行性验证

### 7.1 工作内容

AI 最多初筛 3 个候选市场，优先官方公开结构化文件、公开接口及可稳定解析网页。记录提供方、URL、价格含义、粒度、发布日期规律、历史范围、访问方式和使用限制。

必须实际获取样本并解析，不能用搜索摘要替代验证。禁止绕过登录、验证码、付费墙或访问限制。公开可访问不自动等于允许再分发；不能确认再分发范围时保留来源说明，并限制原始文件公开范围。

默认先以约 2 小时主动研究或每个候选来源两条合法获取路径为探索上限；这是停止无效钻研的预算，不是交付时限。超出后整理证据并切换候选，不无限尝试同一站点。

### 7.2 验收

- 至少一个来源真实下载、解析及质量检查成功。
- 明确区域或节点、DA/RT 类型、单位、时区、时段起止约定。
- 列出已取得的完整日期及历史获取方式。
- 验证数据在目标自动运行环境中的可访问性。
- 单次成功仅证明可行，持续稳定性由 G4 验证。

不足 14 天时允许继续开发，但最终状态必须为“数据积累中”。所有候选失败时交付数据阻塞报告；可完成 fixture 技术演示，但不能称作真实持续分析平台。

## 8. 关卡 G1：最小自动闭环

目标链路：真实数据 → 校验 → 持久化 → 指标 → 简单价格图 → 自动运行 → 预览。

在第一阶段就实现统一入口、日志、失败状态、持久化和定时工作流，不等完整模型写好再部署验证。

验收：

- 本地与自动执行环境均能跑通真实样本。
- 页面显示交易日期、数据来源、最后成功时间。
- 同批重复执行不重复入库、不改变结果含义。
- 下载或校验失败保留上个有效结果。
- fixture 与正式发布路径隔离，正式发布主动拒绝模拟数据。
- 数据持久化后能由一次全新的任务恢复，不依赖上一次临时目录。

## 9. 数据契约与质量控制

### 9.1 最小字段

```text
series_id, market, price_type, location_id, price_definition
market_date, interval_start, interval_end, interval_minutes
price_rmb_mwh, timezone
source_id, source_url, published_at, retrieved_at
raw_sha256, source_revision, schema_version, is_simulated
```

无法从来源确认的 published_at 等字段保留 null 并说明，不以抓取时间冒充发布时间。series_id 由市场、价格类型、地点和价格口径确定。观测唯一键为 series_id + interval_start；修订另存版本，不静默覆盖原始历史。

时间使用明确时区；按来源解释 00:00、24:00 及区间终点，不假定所有表格时间都代表区间起点。时段长度由实际起止计算。

### 9.2 质量规则

检查 Schema、数值、重复、缺失、时区、连续性、日期边界、时段长度和预期覆盖。预期行数依据已验证粒度生成，不统一硬编码为 96。

极端价格不等于错误。市场有效边界须有依据和生效版本；没有依据时只做异常提示，不擅自截断。禁止对缺失价格插值后作为真实回测输入。

每批输出 PASS / WARN / FAIL、检查明细、缺失区间、原始哈希与批次号。FAIL 批次进入隔离区；WARN 必须说明是否影响分析资格。回测只使用符合完整日标准的数据。

### 9.3 持久化与修订

原始数据按内容哈希不可变保存；相同内容不重复归档，新修订保留新版本。处理数据按序列和交易日分区，避免每天重写整段历史。

运行环境的临时磁盘与缓存不作为权威存储。实施时选定持久化位置、恢复方式、容量检查和备份策略，并做恢复验证。原始数据长期保留目标受实际存储和来源条件约束；空间不足时报告，不静默删除。

提交分析结果前完成验证，以原子快照或等效机制切换 last_good 指针。每个快照关联原始哈希、代码版本、配置哈希、模型版本、求解器版本及 run_id。

## 10. 关卡 G2：储能模型与公平回测

### 10.1 默认参数

| 参数 | 默认值 |
| --- | --- |
| 交流侧充、放电功率上限 | 各 100 MW |
| 额定能量 | 200 MWh |
| 初始及终端 SOC | 50% |
| SOC 上、下限 | 90%、10% |
| 往返效率 | 85% |
| 充、放电效率 | 各取 sqrt(0.85) |
| 可用能量窗口 | 160 MWh |
| 衰减系数 | 30 元/电芯侧吞吐 MWh，情景假设 |

100MW/200MWh 中“2 小时”指额定能量/额定功率，不代表在 SOC 窗口与效率限制下可连续向电网满功率输出 2 小时。

### 10.2 模型定义

令 c_t、d_t 为交流侧充电、放电功率（MW），E_t 为电芯侧能量（MWh），p_t 为元/MWh，Δt 为小时，u_t 为二进制充电状态。

$$E_{t+1}=E_t+\eta_c c_t\Delta t-d_t\Delta t/\eta_d$$

$$0\le c_t\le P_cu_t,\qquad 0\le d_t\le P_d(1-u_t)$$

$$E_{min}\le E_t\le E_{max},\qquad E_0=E_T=0.5E_{nom}$$

采用电芯侧双向能量吞吐口径：

$$Q=\sum_t(\eta_c c_t+d_t/\eta_d)\Delta t$$

$$\max\ \sum_t p_t(d_t-c_t)\Delta t-k_{deg}Q$$

默认用 MILP 明确禁止同时充放；不得依靠效率或成本保证互斥，尤其在负电价下。小规模模型的实际性能由基准测试确认，不预先宣称满足某个求解速度。

只有求解器达到规定最优性容差且约束检查通过，才能标记“事后最优”。超时但可行的解若保留，必须标注“可行解/非已证最优”和 gap，不进入理论最优统计。

### 10.3 输出口径

- 放电收入：Σ p_t d_t Δt。
- 购电成本：Σ p_t c_t Δt；负价时允许为负。
- 套利毛收益：放电收入 − 购电成本。
- 衰减成本：k_deg Q。
- 模型净收益：套利毛收益 − 衰减成本。
- 额定容量等效循环 EFC：Q / (2E_nom)。
- 可用窗口等效循环：Q / [2(E_max−E_min)]，若展示则独立命名。

衰减系数是研究假设，不冒充制造商寿命数据。不得把双向吞吐系数与仅按放电量计费的系数直接比较。

### 10.4 两个必需策略

**事后最优：** 使用完整当天价格序列，明确标注“给定模型约束下的事后理论参考”。不同价格口径分别计算；不将其描述成真实可执行收益或跨模型的绝对上限。

**固定时段策略：** 充放电时段和功率政策事先配置，依据电量及效率生成可行调度，不读取当天价格来挑选时段。与最优策略保持相同初末能量、功率、SOC 和成本约束。不可通过未计价的期末补电实现终端平衡。

若固定窗口不能满足终端条件，应在配置验证阶段确定无套利闲置回退并记录原因，或拒绝该配置，不能事后修改窗口美化收益。

### 10.5 回测

输入为日期范围、series_id、策略及配置版本。逐日采用固定初末 SOC，解释这不是跨日联合调度。

只重算新增、修订日期或受配置/模型版本改变影响的范围。各策略必须在共同有效日期上比较；缺失日不是零收益日。展示有效天数、总日历天数、缺失日期和排除原因。

30 日指标按最近 30 个日历日计算并标注有效天数；覆盖不足时标注部分窗口。零循环时每循环收益为 N/A。V1 不使用缺少完整现金流的 IRR，也不将事后理论收益外推为确定年度收益。

## 11. 数据指标与模型测试

### 11.1 基础指标

均价采用按时长加权口径；等间隔时等同算术平均。输出中位数、最大最小值、峰谷差、标准差和分位数，并记录统计定义。

负电价同时报告时段数、累计小时、连续事件数、最长持续小时和负价天数；不要混用“次数”。不同粒度比较以时长为主。

### 11.2 必需模型测试

| 场景 | 预期检查 |
| --- | --- |
| 恒定非负价格、非负成本 | 允许闲置时最优收益约为 0；不凭空盈利 |
| 全零价格、零成本 | 接受多重最优，但不能制造正收益 |
| 先低价后高价 | 满足约束的低买高卖及正确效率损耗 |
| 全负价格 | 允许因吸收能量和损耗产生合理收益；仍禁止同时充放 |
| 极端正负价格 | 功率、SOC、终端和互斥不越界 |
| 衰减成本很高 | 不强制无利可图的循环 |
| 15/30/60 分钟等价构造 | 单位换算与能量、收益一致 |
| 简单小规模可枚举场景 | 与独立手算或穷举结果一致 |

每次模型运行均检查非负功率、能量守恒、边界、互斥和终端容差；容差明确记录。收益由独立汇总函数从调度重新计算。最优策略应在数值容差内不劣于同约束的可行固定策略。

## 12. 关卡 G3：页面与研究材料

页面控制为四个导航区：总览、储能分析、历史研究、方法与来源。手机宽度 375、390、430 px 检查无横向滚动，图表可操作，指标不遮挡。

首页回答：最近有效交易日是哪天、电价如何、负价多长、100MW/200MWh 场景怎样调度、模型收益多少、历史覆盖多少。避免默认写“今天”，尤其是日前价格、延迟发布或历史数据。

状态展示至少包含交易日期、价格类型与地点、数据最后成功时间、页面生成时间、覆盖率和异常说明。无结果时显示 DATA UNAVAILABLE；已有历史时显示最新有效历史和陈旧状态。

报告由固定模板与结构化结果生成，AI 可以润色解释，不能填造数字。没有负荷数据时只解释价格现象，不把负电价直接归因于新能源出力。相关性分析不写成因果结论。

必交材料：README、data_sources.md、methodology.md、技术报告、面试问答、简历描述、手机截图。面试说明围绕问题、数据、模型、结果、限制，并如实说明 AI 辅助开发和本人理解、验证的范围。

## 13. 自动任务与健康状态

日常任务：恢复已确认快照 → 检查来源更新 → 下载新增/修订 → 校验 → 计算受影响日期 → 复核模型 → 生成暂存结果 → 发布新快照 → 更新状态。

每次任务记录 run_id、代码/配置版本、各步骤状态、耗时、输入输出哈希、数据日期和错误类别。健康状态与分析快照分开管理。

状态至少区分：

- healthy：检查与处理正常，数据在预期时效内。
- awaiting_publication：尚未到预计发布时间，不等于抓取失败。
- stale：超过按来源规则定义的时效。
- failed：本次下载、校验、模型或发布失败。
- unavailable：从未取得可发布真实结果。

状态文件记录 last_attempt、last_success、latest_market_date、last_data_change、expected_next_check、error_category。没有新数据但检查正常，不伪造“新增日期”。

分析失败仍应尝试发布健康状态；若连状态发布也失败，页面根据最后检查时间和预期检查时间显示“状态已过期”。旧页面不能永久自称 healthy。

定时平台不被视为精确实时调度器。实施时根据来源发布时间设置有限补查窗口，并补查最近可配置的历史窗口。禁止无限循环抓取。

## 14. 关卡 G4：无人值守试运行

至少观察连续 7 个日历日的定时任务，保留实际运行证据，不以模拟日期或一次手动运行冒充。开发工作完成而观察期未结束时，交付“候选版，试运行中”，不让会话空等，也不提前宣称 V1 稳定。

故障演练使用隔离环境：网络失败、无新数据、缺失区间、Schema 变化、来源修订、重复任务、并发任务、发布失败和全新任务恢复。

通过条件：失败不会污染 last_good；恢复后能补算；并发有锁或等效控制；任务失败能识别；没有人工每日维护；观察期内没有未解决的关键问题。外部来源导致的失败如实记录，不能改成成功率 100%。

## 15. 有界自修复与通知

| 故障 | 自动处理 | 升级条件 |
| --- | --- | --- |
| 瞬时网络错误 | 最多 3 次退避重试 | 超过数据时效阈值 |
| 预计未发布 | 有限补查，标记等待 | 超过来源允许延迟 |
| 解析变化 | 隔离批次、记录原文件 | 核心来源连续阻塞 |
| 模型不满足约束 | 停止该批发布，保留诊断 | 两轮实质修复仍失败 |
| 可选功能缺数据 | 跳过，记录原因 | 不升级 |
| 托管失败 | 保留上一版本，有限重试 | 持续不可用 |
| 账号/费用问题 | 完成其余独立工作 | 合并向用户提出必要事项 |

AI 自修复仅在具备实际执行环境、凭据和授权时运行。普通定时脚本不会自行获得 AI 能力。没有 AI 修复环境时生成可接力诊断包，系统保留正确历史并等待下一次处理。

自修复先在隔离分支修改，测试通过才进入既定发布流程；禁止自动删除历史、弱化约束、扩大权限、切换付费方案或改变数据含义。两轮失败后停止同一路线，选择更简单的合法实现或报告阻塞。

默认在项目状态中记录异常；外发邮件、消息等须有明确授权及已配置渠道。同一故障去重，恢复时记录恢复事件，不每天重复打扰用户。

## 16. 接力文件与变更管理

主控维护以下四份短文件，不重复抄写整份方案：

| 文件 | 内容 |
| --- | --- |
| PROJECT_STATE.md | 当前关卡、任务状态、阻塞、下一项具体动作 |
| DECISIONS.md | 数据口径、技术选择、替代方案与理由 |
| ACCEPTANCE.md | 验收命令、时间、结果和证据路径 |
| RUNBOOK.md | 运行、补数、修订处理、恢复和回滚 |

每次恢复先读取状态和最近有效证据。每次关卡完成或任务阻塞时更新文件。代码、配置、数据版本改变后，记录受影响结果范围；不得用旧模型结果搭配新方法说明。

常规汇报只写：完成了什么、证据在哪里、是否有必须用户决定的事项。避免高频汇报细枝末节。
